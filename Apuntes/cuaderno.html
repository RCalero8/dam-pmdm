1. Outputs

Fuente

Eventos personalizados del componente hijo hacia el padre.

// Hijo
panelClosed = output<void>();
valueChanged = output<number>();
this.valueChanged.emit(7);

// Padre
<custom-slider (valueChanged)="log($event)" />
  • No burbujean por el DOM y distinguen mayúsculas.
  • Solo se declaran en inicializadores de propiedades.
  • Nombres en camelCase, sin prefijo on y sin chocar con eventos del DOM.
  • Forma antigua (sigue válida): @Output() x = new EventEmitter().

3. RouterLink y Router

Fuente

<a routerLink="/settings">Settings</a>           <!-- absoluta -->
<a routerLink="notifications">Notif.</a>          <!-- relativa -->
<a [routerLink]="['user', id]">Usuario</a>         <!-- con parámetro -->

this.router.navigate(['/search'], {queryParams: {sort: 'price'}});
this.router.navigate(['edit'], {relativeTo: this.route});
this.router.navigateByUrl('/products/123?view=details');
Con relativeTo no empieces con / (pasa a absoluta). Los .. van todos en el primer elemento: ['../../settings'].

4. Query params y ruta activa

Fuente

  • Parámetros de ruta (product/:id): route.params.
  • Query params (?sort=price): opcionales, persisten entre navegaciones; ideales para filtros, orden y paginación.
  • Snapshot: foto estática de la ruta; no refleja cambios posteriores.
this.route.queryParams.subscribe(p => {
  const sort = p['sort'] || 'price';
});

this.router.navigate([], {
  queryParams: {sort},
  queryParamsHandling: 'merge',   // conserva los demás
});

routerLinkActive="active" marca el enlace activo; añade [routerLinkActiveOptions]="{exact: true}" para coincidencia exacta y ariaCurrentWhenActive="page" por accesibilidad. isActive() devuelve un signal.

5. Routing

Fuente

En una SPA solo se carga index.html; el router del cliente cambia el contenido según la URL sin recargar.

  • Routes: qué componente va con cada URL.
  • Outlets: dónde se pinta el componente activo.
  • Links: navegar sin recargar.

6. HTTP

Fuente

Buena práctica: encapsular HttpClient en servicios inyectables, no usarlo directo en los componentes.

export class UserService {
  private http = inject(HttpClient);
  getUser(id: string) {
    return this.http.get<User>(`/api/user/${id}`);
  }
}

@if (user$ | async; as user) { <p>{{ user.name }}</p> }
  • Los Observables son fríos: sin subscribe no hay petición, y cada suscripción lanza una nueva.
  • Cancelar la suscripción aborta la petición; async pipe y toSignal limpian solos.
  • El tipo genérico es una aserción: no se verifica.
  • HttpParams y HttpHeaders son inmutables.
  • Errores como HttpErrorResponse (red y timeout: status 0); usa catchError y retry().

Lo que cambia con el tiempo debe leerse desde un signal. En [class] y [style] con arrays u objetos hay que crear una instancia nueva para que Angular detecte el cambio. track es obligatorio en @for.

8. Signals

Fuente

Un signal envuelve un valor y permite a Angular saber dónde se lee y cuándo cambia (reactividad).

const name = signal('Morgan');
name();                              // leer
name.set('Jaime');                   // cambiar
name.update(n => n.toUpperCase());   // cambiar según el anterior

const upper = computed(() => name().toUpperCase()); // derivado, solo lectura
signal() guarda estado, computed() lo deriva, se lee con ().

9. Reactive forms

Fuente

El modelo se define en la clase y es la fuente de verdad. Importa ReactiveFormsModule.

ClaseFunción
FormControlUn campo: new FormControl('') con [formControl]
FormGroupGrupo con nombre: [formGroup] y formControlName; anidado con formGroupName
FormArrayColección dinámica sin nombre: formArrayName, .push()
FormBuilderAtajo: fb.group({firstName: ['', Validators.required]})
 
profileForm = new FormGroup({
  firstName: new FormControl('', Validators.required),
  address: new FormGroup({ city: new FormControl('') }),
});

<form [formGroup]="profileForm">
  <input formControlName="firstName" />
  <div formGroupName="address"><input formControlName="city" /></div>
</form>
  • setValue() reemplaza todo y exige la estructura exacta; patchValue() actualiza solo lo indicado.
  • valueChanges emite cada cambio; status: VALID, INVALID, PENDING o DISABLED (un grupo inválido invalida a su padre).
  • Estados touched/dirty se actualizan solos; también con markAsTouched(), markAllAsDirty()...
  • {emitEvent: false} evita emitir eventos; {onlySelf: true} no notifica al padre.
Reactive = modelo explícito en la clase, FormControl/FormGroup/FormArray, validación con funciones.

10. Validadores

Incorporados · Personalizados

Incorporados

Los atributos de template-driven (required, minlength...) existen como funciones de la clase Validators. Varios van en un array; uno solo, directo.

name: new FormControl('', [Validators.required, Validators.minLength(4)]),
skill: new FormControl('', Validators.required),

postalCode.addValidators([Validators.required, Validators.pattern(/^\d{5}$/)]);
@if (name.invalid && (name.dirty || name.touched)) {
  @if (name.hasError('required')) { <div>Name is required.</div> }
  @if (name.hasError('minlength')) { <div>Mínimo 4 caracteres.</div> }
}
  • invalid: hay algún error. dirty: el usuario cambió el valor. touched: salió del campo.
  • Muestra errores solo si dirty o touched; mantén required en la plantilla por accesibilidad.

Personalizados

Una fábrica que devuelve una función: recibe el control y devuelve null si es válido, o un objeto de error.

export function forbiddenNameValidator(nameRe: RegExp): ValidatorFn {
  return (control: AbstractControl): ValidationErrors | null => {
    const forbidden = nameRe.test(control.value);
    return forbidden ? {forbiddenName: {value: control.value}} : null;
  };
}

// Reactive: se pasa directamente
name: new FormControl('', [Validators.required, forbiddenNameValidator(/bob/i)])

En template-driven hace falta una directiva registrada en NG_VALIDATORS:

@Directive({
  selector: '[appForbiddenName]',
  providers: [{provide: NG_VALIDATORS, useExisting: forwardRef(() => ForbiddenValidatorDirective), multi: true}],
})
export class ForbiddenValidatorDirective implements Validator {
  forbiddenName = input<string>('', {alias: 'appForbiddenName'});
  validate(control: AbstractControl): ValidationErrors | null {
    return this.forbiddenName()
      ? forbiddenNameValidator(new RegExp(this.forbiddenName(), 'i'))(control) : null;
  }
}
Usa useExisting, no useClass: el validador debe ser esa instancia, la que tiene el valor enlazado. Los validadores asíncronos devuelven Promise u Observable que emita null o error; el Observable debe completarse (first, take...).
