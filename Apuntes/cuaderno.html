1. Eventos personalizados con outputs

Fuente: angular.dev/guide/components/outputs

Un componente define eventos propios asignando a una propiedad la función output(). Esas propiedades se llaman outputs y se usan como eventos nativos (por ejemplo, click).

// Hijo
export class ExpandablePanel {
  panelClosed = output<void>();
}

// Padre
<expandable-panel (panelClosed)="savePanelState()" />

// Emitir
this.panelClosed.emit();

output() devuelve un OutputEmitterRef, que es el que tiene el método emit.

  • Los eventos personalizados no burbujean por el DOM.
  • Los nombres de output distinguen mayúsculas y minúsculas.
  • Los outputs se heredan al extender una clase de componente.
  • output() solo puede llamarse en inicializadores de propiedades de componentes y directivas.

Emitir datos

this.valueChanged.emit(7);                              // primitivo
this.thumbDropped.emit({pointerX: 123, pointerY: 456}); // objeto

<custom-slider (valueChanged)="logValue($event)" />

// Padre
logValue(value: number) { ... }

En la plantilla, los datos del evento llegan en la variable $event.

Alias

changed = output({alias: 'valueChanged'});
<custom-slider (valueChanged)="saveVolume()" />

El alias solo afecta a la plantilla, no al uso en TypeScript. En general conviene evitarlo; es útil para renombrar manteniendo el nombre antiguo o para evitar colisiones con eventos DOM.

Suscripción programática

Si creas el componente dinámicamente, puedes suscribirte al output con subscribe. Angular limpia las suscripciones al destruir el componente, pero también puedes cancelar a mano con unsubscribe().

const ref: ComponentRef<SomeComponent> = viewContainerRef.createComponent(/*...*/);

const sub = ref.instance.someEventProperty.subscribe((eventData) => {
  console.log(eventData);
});

sub.unsubscribe();

Cómo nombrar los eventos

  • No uses nombres que choquen con eventos del DOM (como los de HTMLElement).
  • No pongas prefijos como en los selectores de componentes.
  • Usa siempre camelCase y evita prefijar con on.

Forma antigua: @Output y EventEmitter

Sigue totalmente soportada, pero el equipo de Angular recomienda output() en proyectos nuevos.

@Output() panelClosed = new EventEmitter<void>();
@Output('valueChanged') changed = new EventEmitter<number>(); // con alias

// También en el decorador del componente (útil con herencia)
@Component({ outputs: ['valueChanged'] })
@Component({ outputs: ['valueChanged: volumeChanged'] }) // con alias

2. Formularios template-driven

Fuente: angular.dev/guide/forms (sección «Setup in template-driven forms»)

Angular ofrece dos enfoques: reactive y template-driven. Los dos capturan la entrada del usuario, la validan, crean un modelo de datos y permiten seguir los cambios. Se construyen sobre las mismas clases base: FormControl, FormGroup, FormArray y ControlValueAccessor.

Configuración en template-driven

El modelo del formulario es implícito: la directiva NgModel crea y gestiona un FormControl para cada elemento. La fuente de verdad es la plantilla.

import {Component, signal} from '@angular/core';
import {FormsModule} from '@angular/forms';

@Component({
  selector: 'app-template-favorite-color',
  template: ` Favorite Color: <input type="text" [(ngModel)]="favoriteColor" /> `,
  imports: [FormsModule],
})
export class FavoriteColorTemplate {
  favoriteColor = signal('');
}

Claves: importar FormsModule y usar [(ngModel)] (two-way binding), aquí enlazado a un signal.

Comparación con reactive forms

ReactiveTemplate-driven
Modelo del formularioExplícito, creado en la claseImplícito, creado por directivas
Modelo de datosEstructurado e inmutableNo estructurado y mutable
Flujo de datosSíncronoAsíncrono
ValidaciónFuncionesDirectivas

Cuándo usar cada uno

  • Reactive: más escalables, reutilizables y fáciles de testear. Para formularios importantes en la app.
  • Template-driven: para formularios simples (por ejemplo, suscribirse a una lista de correo). Se añaden fácil pero escalan peor.

Flujo de datos en template-driven

Vista → modelo: el usuario escribe, el input emite input, el ControlValueAccessor llama a setValue() en el FormControl, este emite por valueChanges, y NgModel emite ngModelChange, con lo que se actualiza la propiedad enlazada.

Modelo → vista: al cambiar la propiedad, durante la detección de cambios se ejecuta ngOnChanges en NgModel, que encola una tarea asíncrona para fijar el valor del FormControl; en el siguiente tick se aplica y el accessor actualiza el input.

Esa segunda ronda de detección de cambios evita errores ExpressionChangedAfterItHasBeenChecked.

Testing

Probar template-driven exige entender la detección de cambios. Se espera a que la vista se estabilice con await fixture.whenStable():

it('should update the favorite color on the input field', async () => {
  component.favoriteColor.set('Blue');
  await fixture.whenStable();
  const input = fixture.nativeElement.querySelector('input');
  expect(input.value).toBe('Blue');
});
Template-driven = FormsModule + [(ngModel)]; sencillo, pero asíncrono, mutable y menos escalable que reactive.

3. Navegar con RouterLink y Router

Fuente: angular.dev/guide/routing/navigate-to-routes

RouterLink es la forma declarativa de navegar: se usan anclas <a> normales, pero con routerLink en lugar de href.

import {RouterLink} from '@angular/router';

@Component({
  template: `
    <nav>
      <a routerLink="/user-profile">User profile</a>
      <a routerLink="/settings">Settings</a>
    </nav>
  `,
  imports: [RouterLink],
})
export class App {}

Rutas absolutas y relativas

Se prefieren las URL relativas porque son más fáciles de mantener: no necesitan conocer su posición absoluta en la jerarquía de rutas.

<!-- Equivalentes: navegan a /dashboard -->
<a routerLink="dashboard">Dashboard</a>
<a [routerLink]="['dashboard']">Dashboard</a>

<!-- Con parámetros dinámicos: sintaxis de array -->
<a [routerLink]="['user', currentUserId]">Current User</a>

Si empieza por / es respecto a la raíz; si no, es relativa a la URL actual. Estando en /settings:

<!-- Ambos van a /settings/notifications -->
<a routerLink="notifications">Notifications</a>
<a routerLink="/settings/notifications">Notifications</a>

<a routerLink="/team/123/user/456">User 456</a>
<a [routerLink]="['/team', teamId, 'user', userId]">Current User</a>

Navegación programática

Inyectando Router puedes navegar desde TypeScript según lógica, acciones del usuario o estado.

router.navigate() (array de segmentos)

private router = inject(Router);

this.router.navigate(['/profile']);                 // estándar
this.router.navigate(['/users', userId]);           // con parámetro de ruta
this.router.navigate(['/search'], {                 // con query params
  queryParams: {category: 'books', sort: 'price'},
});
this.router.navigate(['/products', {featured: true, onSale: true}]); // matrix params

Con la opción relativeTo se navega respecto a la ruta del componente:

private route = inject(ActivatedRoute);

this.router.navigate(['edit'], {relativeTo: this.route});          // /users/123 → /users/123/edit
this.router.navigate(['..'], {relativeTo: this.route});            // /users/123 → /users
this.router.navigate(['..', 'list'], {relativeTo: this.route});    // /users/123 → /users/list
  • Para subir varios niveles, todos los .. deben ir en el primer elemento del array: ['../../settings']. Los demás elementos se toman como segmentos literales.
  • Con relativeTo, nunca empieces el primer comando con /: la navegación pasaría a absoluta e ignoraría relativeTo (['/edit'] lleva a /edit).

router.navigateByUrl() (string de URL)

Ideal con una URL completa y navegación absoluta, por ejemplo con URLs externas o deep linking.

router.navigateByUrl('/products');
router.navigateByUrl('/products/123?view=details#reviews');
router.navigateByUrl('/search?category=books&sortBy=price');
router.navigateByUrl('/sales-awesome;isOffer=true;showModal=false');

// Reemplazar la URL actual en el historial
router.navigateByUrl('/checkout', {replaceUrl: true});

Mostrar otra URL en la barra de direcciones

La opción browserUrl separa lo que se renderiza de lo que se ve en la barra. Útil, por ejemplo, para mostrar una página de error sin cambiar la URL que el usuario intentó visitar.

router.navigateByUrl('/not-found', {browserUrl: '/products/missing-item'});

<!-- También en RouterLink -->
<a [routerLink]="['/dashboard']" [browserUrl]="'/home'">Go to Dashboard</a>

browserUrl también acepta un UrlTree (creado con router.createUrlTree([...])). Solo afecta a lo que aparece en la barra del navegador.

4. Leer el estado de la ruta y query params

Fuente: angular.dev/guide/routing/read-route-state

ActivatedRoute

Servicio de @angular/router con toda la información de la ruta actual.

private activatedRoute = inject(ActivatedRoute);
PropiedadQué contiene
urlObservable con un array de UrlSegment
dataObservable con los datos de la ruta (y valores de resolvers)
paramsObservable con los parámetros de la ruta
queryParamsObservable con los query params, disponibles para todas las rutas
resourcesRegistro opcional de instancias Resource (con withRouterResources)

Snapshots

Un snapshot es una foto estática del estado del router en un momento dado: parámetros, datos y rutas hijas. No refleja cambios posteriores.

this.userId = this.route.snapshot.paramMap.get('id');

const snapshot = this.route.snapshot;
snapshot.url;         // segmentos
snapshot.params;      // {id: '123'}
snapshot.queryParams; // {role: 'admin', status: 'active'}

Parámetros de ruta

Pasan datos por la URL (un id de usuario o producto). Se definen con : en la ruta y se leen suscribiéndose a route.params.

const routes: Routes = [{path: 'product/:id', component: Product}];

this.activatedRoute.params.subscribe((params) => {
  this.productId.set(params['id']);
});

Query parameters

Son datos opcionales que se añaden a la URL sin afectar a la estructura de la ruta. A diferencia de los parámetros de ruta, pueden persistir entre navegaciones; son perfectos para filtros, orden, paginación y otros estados de la interfaz.

// /products?category=electronics
router.navigate(['/products'], {
  queryParams: {category: 'electronics'},
});

// /products?category=electronics&sort=price&page=1
router.navigate(['/products'], {
  queryParams: {category: 'electronics', sort: 'price', page: 1},
});

Lectura reactiva y actualización desde un select:

constructor() {
  this.route.queryParams.subscribe((params) => {
    const sort = params['sort'] || 'price';
    const page = Number(params['page']) || 1;
    this.loadProducts(sort, page);
  });
}

updateSort(event: Event) {
  const sort = (event.target as HTMLSelectElement).value;
  this.router.navigate([], {
    queryParams: {sort},
    queryParamsHandling: 'merge', // conserva los demás query params
  });
}
Al cambiar los query params en la URL, se dispara el cambio en queryParams, que vuelve a cargar la lista. Con queryParamsHandling: 'merge' se mantienen los demás parámetros.

Matrix parameters

Parámetros opcionales de un segmento concreto de la URL (no de toda la ruta). Usan ; y no hace falta declararlos en la configuración de rutas. Se leen también por params.

this.router.navigate(['/awesome-products', {view: 'grid', filter: 'new'}]);
// → /awesome-products;view=grid;filter=new

RouterLinkActive: detectar la ruta activa

<a class="button"
   routerLink="/about"
   routerLinkActive="active-button"
   ariaCurrentWhenActive="page">About</a>

<!-- Varias clases: string con espacios o array -->
<a routerLink="/user/bob" routerLinkActive="class1 class2">Bob</a>
<a routerLink="/user/bob" [routerLinkActive]="['class1', 'class2']">Bob</a>
  • routerLinkActive por sí solo no pone aria-current; usa ariaCurrentWhenActive por accesibilidad.
  • Por defecto cuenta como coincidencia cualquier ancestro de la ruta: en /user/jane/role/admin se activan los enlaces a /user/jane y /user/jane/role/admin.
  • Para coincidencia exacta: [routerLinkActiveOptions]="{exact: true}".
  • También puede ir en un elemento ancestro (por ejemplo, un <div> que contiene varios enlaces).
// exact: true equivale a:
{ paths: 'exact', fragment: 'ignored', matrixParams: 'ignored', queryParams: 'exact' }
// exact: false equivale a:
{ paths: 'subset', fragment: 'ignored', matrixParams: 'ignored', queryParams: 'subset' }

isActive(): ¿está activa esta URL?

Devuelve un signal computed que se actualiza solo cuando cambia el estado del router.

isSettingsActive = isActive('/settings', this.router, {
  paths: 'subset',
  queryParams: 'ignored',
  fragment: 'ignored',
  matrixParams: 'ignored',
});

<div [class.active]="isSettingsActive()">

5. Routing: visión general

Fuente: angular.dev/guide/routing

El routing cambia lo que ve el usuario dentro de una SPA (aplicación de una sola página). El Angular Router (@angular/router) es la librería oficial y viene incluida en los proyectos creados con Angular CLI.

¿Por qué hace falta en una SPA?

  • En una web tradicional, cada URL nueva provoca una petición al servidor y se reemplaza toda la página.
  • En una SPA solo se pide la primera página (index.html); luego un router en el cliente decide qué contenido mostrar según la URL, sin recargar la página.

Las tres piezas

PiezaFunción
RoutesDefinen qué componente se muestra para cada URL
OutletsMarcadores en la plantilla donde se carga el componente de la ruta activa
LinksPermiten navegar entre rutas sin recargar la página

Otras funcionalidades

  • Rutas anidadas y navegación programática
  • Parámetros de ruta, query params y comodines
  • Información de la ruta activa con ActivatedRoute
  • Carga de datos con resources y resolvers
  • Efectos de transición de vista
  • Guards de navegación

6. HTTP: buenas prácticas

Fuente: angular.dev/guide/http/making-requests

Buena práctica principal

HttpClient puede inyectarse directamente en un componente, pero se recomienda crear servicios inyectables reutilizables que aíslen y encapsulen el acceso a datos.

@Service()
export class UserService {
  private http = inject(HttpClient);

  getUser(id: string): Observable<User> {
    return this.http.get<User>(`/api/user/${id}`);
  }
}

En el componente, @if + async pipe renderizan la interfaz solo cuando los datos ya han cargado:

@Component({
  imports: [AsyncPipe],
  template: `
    @if (user$ | async; as user) {
      <p>Name: {{ user.name }}</p>
      <p>Biography: {{ user.biography }}</p>
    }
  `,
})
export class UserProfile {
  userId = input.required<string>();
  user$!: Observable<User>;
  private userService = inject(UserService);

  constructor() {
    effect(() => {
      this.user$ = this.userService.getUser(this.userId());
    });
  }
}

Conceptos de la misma página

Observables «fríos»

  • No se hace ninguna petición hasta que alguien se suscribe. Piensa en el Observable como un plano de la petición.
  • Cada suscripción lanza una nueva petición al backend.
  • Cancelar la suscripción aborta la petición en curso. El async pipe lo hace solo si el usuario se va de la página; switchMap también limpia peticiones obsoletas.
  • Lo habitual es que se completen al llegar la respuesta, por lo que no suele haber fugas de memoria. Aun así, conviene limpiar al destruir el componente; async pipe y toSignal lo hacen automáticamente.

Peticiones principales

http.get<Config>('/api/config').subscribe(config => { /* ... */ });
http.post<Config>('/api/config', newConfig).subscribe(config => { /* ... */ });
  • El tipo genérico es una aserción: HttpClient no comprueba que los datos reales coincidan con él.
  • Hay que hacer .subscribe() también en las peticiones de modificación (POST, etc.); si no, no se envían.
responseTypeDevuelve
'json' (por defecto)JSON del tipo genérico dado
'text'string
'arraybuffer'ArrayBuffer con los bytes
'blob'Blob

Si extraes las opciones a una variable, usa literales: responseType: 'text' as const (lo mismo con observe).

Parámetros y cabeceras

http.get('/api/config', { params: {filter: 'all'} });
http.get('/api/config', { headers: {'X-Debug-Level': 'verbose'} });

const baseParams = new HttpParams().set('filter', 'all');
http.get('/api/config', { params: baseParams.set('details', 'enabled') });

HttpParams y HttpHeaders son inmutables: métodos como set() o append() devuelven una instancia nueva.

Respuesta completa y eventos

http.get<Config>('/api/config', {observe: 'response'}).subscribe(res => {
  console.log(res.status, res.body);
});

http.get('/api/download', {reportDownloadProgress: true, observe: 'events'})
  .subscribe(event => {
    if (event.type === HttpEventType.DownloadProgress) { /* event.loaded / event.total */ }
  });

El backend fetch (por defecto) no admite eventos de subida; para ellos configura provideHttpClient(withXhr()).

Errores y timeouts

  • Tres tipos de fallo: error de red, timeout y respuesta de error del backend. Todos llegan como HttpErrorResponse por el canal de error.
  • Errores de red y timeout tienen status 0.
  • Operadores útiles de RxJS: catchError (convertir el error en un valor para la UI) y retry() (reintentar ante fallos transitorios).
  • timeout: 3000 (ms) aborta la petición y emite un error; solo mide la petición al backend, no el retraso de los interceptores.

Opciones avanzadas de fetch

OpciónPara qué
keepaliveLa petición sobrevive a la página (analíticas, logs)
cacheControla el uso de la caché HTTP (force-cache, no-cache, only-if-cached)
priorityhigh / low / auto; ayuda a los Core Web Vitals
modesame-origin, cors (defecto), no-cors
redirectfollow (defecto), manual, error
credentialsomit, same-origin (defecto), include
referrer / referrerPolicyQué información de referencia se envía

withCredentials: true tiene prioridad sobre credentials y equivale a credentials: 'include'. Evita mezclar ambas opciones.
En SSR con Node.js, mode: 'same-origin' no restringe las peticiones del servidor (no hay comprobaciones CORS de navegador): valida las URLs influidas por el usuario con una lista permitida. Además, credentials: 'include' no reenvía cookies automáticamente; reenvía cabeceras de credenciales solo a orígenes de confianza.
Encapsula HttpClient en servicios, recuerda que los Observables son fríos (hay que suscribirse) y limpia las suscripciones con async pipe o toSignal.

7. Binding de texto, propiedades y atributos

Fuente: v20.angular.dev/guide/templates/binding

Un binding crea una conexión dinámica entre la plantilla y los datos del componente: si los datos cambian, la plantilla se actualiza.

Interpolación de texto

Con dobles llaves Angular se encarga de evaluar la expresión y mantenerla actualizada. Todo valor se convierte a string (objetos y arrays usan su toString).

Los valores que cambian con el tiempo deben leerse desde signals: Angular rastrea los signals leídos en la plantilla y re-renderiza cuando cambian.

template: `
  <!-- Puede no actualizarse si cambia -->
  <p>{{ welcomeMessage }}</p>
  <!-- Se actualiza siempre que cambie el signal -->
  <p>Your color preference is {{ theme() }}.</p>
`
// welcomeMessage = "Welcome..."; theme = signal('dark');

Propiedades y atributos con corchetes

  • Propiedad nativa del DOM: <button [disabled]="isFormValid()">
  • Input de un componente: <my-listbox [value]="mySelection()" />
  • Propiedad de una directiva: <img [ngSrc]="profilePhotoUrl()">
  • Atributo (ARIA, SVG, sin propiedad DOM equivalente): [attr.role]="listRole()". Si el valor es null, Angular elimina el atributo.

Interpolación dentro de propiedades y atributos

<!-- Se trata como binding de propiedad -->
<img src="profile-photo.jpg" alt="Profile photo of {{ firstName() }}">

<!-- Para atributos, prefijo attr. -->
<button attr.aria-label="Save changes to {{ objectType() }}">

Clases CSS

<!-- Una clase concreta, según si el valor es truthy -->
<ul [class.expanded]="isExpanded()">

<!-- Binding a class completo -->
<ul [class]="listClasses">          <!-- string: 'full-width outlined' -->
<section [class]="sectionClasses()"> <!-- array: ['expandable', 'elevated'] -->
<button [class]="buttonClasses()">    <!-- objeto: {highlighted: true, embiggened: false} -->
Valor de classTipo TypeScript
String con clases separadas por espaciosstring
Array de clasesstring[]
Objeto: nombre de clase → truthy/falsyRecord<string, any>
  • Angular combina las clases estáticas, el binding de class y los bindings de clases concretas. No garantiza un orden.
  • Con arrays y objetos compara por referencia (===): hay que crear una instancia nueva al modificarlos.
Las claves con varias clases separadas por espacios y las mutaciones de objetos no funcionan con los bindings de clase; para eso existe la directiva ngClass.

Estilos CSS

<section [style.display]="isExpanded() ? 'block' : 'none'">
<section [style.height.px]="sectionHeightInPixels()">   <!-- con unidad -->

<ul [style]="listStyles()">       <!-- string: 'display: flex; padding: 8px' -->
<section [style]="sectionStyles()"> <!-- objeto: {border: '1px solid black', 'font-weight': 'bold'} -->

Igual que con las clases, si el binding es un objeto, hay que crear una instancia nueva para que Angular detecte el cambio.

8. Plantillas (esenciales)

Fuente: v20.angular.dev/essentials/templates

Las plantillas de un componente no son HTML estático: pueden usar datos de la clase y registrar manejadores de eventos del usuario.

Texto dinámico: {{ }}

@Component({
  selector: 'user-profile',
  template: `<h1>Profile for {{userName()}}</h1>`,
})
export class UserProfile {
  userName = signal('pro_programmer_123');
}
// this.userName.set('cool_coder_789')  →  la vista se actualiza sola

Propiedades y atributos: [ ]

<button [disabled]="!isValidUserId()">Save changes</button>

<!-- Atributos HTML: prefijo attr. -->
<ul [attr.role]="listRole()">

Eventos del usuario: ( )

<button (click)="cancelSubscription()">Cancel subscription</button>

<!-- Para recibir el objeto del evento: $event -->
<button (click)="cancelSubscription($event)">Cancel subscription</button>

Control de flujo: @if y @for

@if (isAdmin()) {
  <h2>Admin settings</h2>
} @else {
  <h2>User settings</h2>
}

<ul class="user-badge-list">
  @for (badge of badges(); track badge.id) {
    <li class="user-badge">{{badge.name}}</li>
  }
</ul>

9. Signals

Fuente: v20.angular.dev/essentials/signals

Un signal es un envoltorio ligero alrededor de un valor. Es la forma de crear y gestionar estado en Angular. Angular sabe dónde se lee cada signal y cuándo cambia, y con eso actualiza lo necesario (por ejemplo, el DOM). A esa capacidad se le llama reactividad.

Crear, leer y modificar

import {signal} from '@angular/core';

const firstName = signal('Morgan');   // crear

console.log(firstName());             // leer: se llama como una función

firstName.set('Jaime');               // cambiar con un valor nuevo
firstName.update(name => name.toUpperCase()); // cambiar según el valor anterior
  • signal(valorInicial) crea el signal.
  • Se lee llamándolo: firstName().
  • set() sustituye el valor; update() lo calcula a partir del anterior.

computed: valores derivados

Un computed es un signal cuyo valor se calcula a partir de otros signals. Es de solo lectura (no tiene set ni update) y se recalcula solo cuando cambia alguno de los signals que lee.

import {signal, computed} from '@angular/core';

const firstName = signal('Morgan');
const firstNameCapitalized = computed(() => firstName().toUpperCase());

console.log(firstNameCapitalized()); // MORGAN
firstName.set('Jaime');
console.log(firstNameCapitalized()); // JAIME

Signals dentro de un componente

@Component({/* ... */})
export class UserProfile {
  isTrial = signal(false);
  isTrialExpired = signal(false);
  showTrialDuration = computed(() => this.isTrial() && !this.isTrialExpired());

  activateTrial() {
    this.isTrial.set(true);
  }
}
Estado con signal(), derivados con computed(), lectura con paréntesis y escritura con set/update.

10. Reactive forms

Fuente: angular.dev/guide/forms/reactive-forms

En los reactive forms el modelo se define explícitamente en la clase y es la fuente de verdad. Hay que importar ReactiveFormsModule en el array imports del componente.

FormControl: un solo campo

FormControl gestiona un único campo. En la plantilla se vincula con [formControl].

name = new FormControl('');

<input type="text" [formControl]="name" />

FormGroup: varios controles con nombre

Agrupa controles con nombre; es el formulario de nivel superior. En la plantilla, [formGroup] en el <form> y formControlName en cada campo.

profileForm = new FormGroup({
  firstName: new FormControl(''),
  lastName: new FormControl(''),
});

<form [formGroup]="profileForm">
  <input type="text" formControlName="firstName" />
  <input type="text" formControlName="lastName" />
</form>

Grupos anidados

Un FormGroup puede contener otro. En la plantilla se usa formGroupName.

profileForm = new FormGroup({
  firstName: new FormControl(''),
  address: new FormGroup({
    street: new FormControl(''),
    city: new FormControl(''),
  }),
});

<div formGroupName="address">
  <input type="text" formControlName="street" />
  <input type="text" formControlName="city" />
</div>

FormBuilder

Servicio que simplifica la creación de controles, grupos y arrays. Cada valor es un array con el valor inicial y, opcionalmente, los validadores.

private formBuilder = inject(FormBuilder);

profileForm = this.formBuilder.group({
  firstName: ['', Validators.required],
  lastName: [''],
});

FormArray: colección dinámica

Colección de controles sin nombre, útil cuando el número de campos cambia (por ejemplo, alias o teléfonos).

aliases: this.formBuilder.array([this.formBuilder.control('')]),

get aliases() {
  return this.profileForm.get('aliases') as FormArray;
}

addAlias() {
  this.aliases.push(this.formBuilder.control(''));
}

<div formArrayName="aliases">
  @for (alias of aliases.controls; track $index; let i = $index) {
    <input type="text" [formControlName]="i" />
  }
</div>
FormArrayDirective permite usar un FormArray como modelo raíz de un <form>.

Validación y estado

Los validadores se añaden como segundo elemento del array del FormBuilder (o como segundo argumento de FormControl).

firstName: ['', Validators.required],

profileForm.status   // 'VALID' | 'INVALID' | 'PENDING' | 'DISABLED'

Un grupo con algún control inválido propaga el estado inválido a su padre.

Leer y actualizar valores

  • control.value: instantánea del valor actual.
  • valueChanges: observable que emite cada vez que cambia el valor.
  • setValue(): reemplaza el valor completo y exige la estructura exacta.
  • patchValue(): actualiza solo las propiedades indicadas; falla en silencio si la estructura no encaja.
this.name.setValue('Nancy');

this.profileForm.patchValue({ firstName: 'Nancy' });

Estado de los controles

Par de estadosSignificado
touched / untouchedEl usuario ha salido (o no) del campo
dirty / pristineEl usuario ha cambiado (o no) el valor

Se actualizan solos con la interacción, pero también se pueden forzar: markAsTouched(), markAsUntouched(), markAsDirty(), markAsPristine(), markAllAsDirty() y markAllAsTouched().

La propiedad events es un observable unificado que emite ValueChangeEvent, StatusChangeEvent, PristineChangeEvent, TouchedChangeEvent, FormResetEvent y FormSubmittedEvent.

Controlar la emisión y la propagación

  • {emitEvent: false}: no emite valueChanges ni statusChanges.
  • {onlySelf: true}: la actualización se queda en el control actual y no notifica al padre.

Utilidades de tipo

isFormControl, isFormGroup, isFormRecord e isFormArray son type guards; resultan útiles dentro de validadores personalizados.

En aplicaciones zoneless, modificar el modelo (por ejemplo, con push()) no programa la detección de cambios. Si la plantilla depende de esos cambios estructurales, llama a markForCheck() desde valueChanges.

11. Validadores incorporados

Fuente: angular.dev/guide/forms/form-validation (sección «Built-in validator functions»)

Los mismos validadores que existen como atributos en los formularios template-driven (required, minlength...) están disponibles como funciones de la clase Validators. La lista completa está en la referencia de la API de Validators.

Usarlos en un FormControl

Varios validadores se pasan como array; un único validador puede pasarse directamente.

actorForm = new FormGroup({
  name: new FormControl(this.actor.name, [
    Validators.required,
    Validators.minLength(4),
    forbiddenNameValidator(/bob/i), // validador personalizado
  ]),
  role: new FormControl(this.actor.role),
  skill: new FormControl(this.actor.skill, Validators.required),
});

get name() {
  return this.actorForm.get('name');
}

get skill() {
  return this.actorForm.get('skill');
}
ValidadorQué comprueba
Validators.requiredEl campo no puede estar vacío
Validators.minLength(4)Longitud mínima de 4 caracteres
Validators.pattern(/^\d{5}$/)El valor debe cumplir la expresión regular
La página solo ilustra estos tres; el resto de validadores de Validators están en la referencia de la API.

Gestionar validadores dinámicamente

Se pueden añadir validadores a un control ya creado:

postalCodeControl.addValidators([Validators.required, Validators.pattern(/^\d{5}$/)]);

Mostrar los errores

12. Validadores personalizados

Fuente: angular.dev/guide/forms/form-validation (sección «Defining custom validators»)

Un validador personalizado es una fábrica: recibe parámetros (por ejemplo, una expresión regular) y devuelve una función validadora. Esa función recibe el control y devuelve null si el valor es válido, o un objeto de error si no lo es. La clave del objeto es el nombre de la validación ('forbiddenName') y su valor puede llevar datos para el mensaje.

/** El nombre de un actor no puede coincidir con la expresión regular dada */
export function forbiddenNameValidator(nameRe: RegExp): ValidatorFn {
  return (control: AbstractControl): ValidationErrors | null => {
    const forbidden = nameRe.test(control.value);
    return forbidden ? {forbiddenName: {value: control.value}} : null;
  };
}

En reactive forms

Se pasa la función directamente al FormControl, sola o dentro del array de validadores.

actorForm = new FormGroup({
  name: new FormControl(this.actor.name, [
    Validators.required,
    Validators.minLength(4),
    forbiddenNameValidator(/bob/i), // así se pasa el validador personalizado
  ]),
  role: new FormControl(this.actor.role),
  skill: new FormControl(this.actor.skill, Validators.required),
});

En template-driven forms

Hace falta una directiva que envuelva la función validadora y se registre con el proveedor NG_VALIDATORS.

@Directive({
  selector: '[appForbiddenName]',
  providers: [
    {
      provide: NG_VALIDATORS,
      useExisting: forwardRef(() => ForbiddenValidatorDirective),
      multi: true,
    },
  ],
})
export class ForbiddenValidatorDirective implements Validator {
  readonly forbiddenName = input<string>('', {alias: 'appForbiddenName'});

  validate(control: AbstractControl): ValidationErrors | null {
    return this.forbiddenName()
      ? forbiddenNameValidator(new RegExp(this.forbiddenName(), 'i'))(control)
      : null;
  }
}

Después se activa añadiendo el selector al input:

<input
  type="text"
  id="name"
  name="name"
  class="form-control"
  required
  minlength="4"
  appForbiddenName="bob"
  [(ngModel)]="actor.name"
  #name="ngModel"
/>
Registra la directiva con useExisting, no con useClass: el validador registrado debe ser esa misma instancia de ForbiddenValidatorDirective, la que tiene forbiddenName enlazado a «bob». Con useClass se crearía una instancia nueva sin ese valor.

Validadores asíncronos

Son similares, pero devuelven una Promise o un Observable que emite null o un error. El formulario usa el último valor emitido.

El Observable debe completarse. Si es infinito, límitalo con operadores como first, last, take o takeUntil.
Muestra los mensajes de error solo cuando el control esté dirty o touched.
